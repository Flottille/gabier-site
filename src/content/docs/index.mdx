## Build

Gabier is not on crates.io yet, so you build it from the repository. One release profile, one static-ish
binary, no runtime dependency.

```shellsession
$ git clone https://github.com/Flottille/gabier
$ cd gabier
$ cargo build --release
```

<Callout title="No Rust on the server?">
  Build a fully static Linux binary anywhere with Docker, then copy it over:
  <code>docker run --rm -v "$PWD:/app" -w /app rust:1-slim sh -c "rustup target add
  x86_64-unknown-linux-musl && cargo build --release --target x86_64-unknown-linux-musl"</code>
</Callout>

## Install

`install.sh` does the whole job: it creates a dedicated `gabier` service account with no shell and no home,
installs the binary and the hardened unit, drops an example config and enables the service at boot.

```shellsession
$ sudo ./install.sh
# or, with a binary built elsewhere:
$ sudo ./install.sh /tmp/gabier
```

It lays down:

| Path | What |
| --- | --- |
| `/usr/local/bin/gabier` | the binary |
| `/etc/gabier/config.toml` | your config, mode `0640`, group `gabier` |
| `/etc/gabier/env` | optional, for the webhook secrets |
| `/etc/systemd/system/gabier.service` | the hardened unit |

An existing `config.toml` is never overwritten, so re-running the script is how you upgrade.

## Configure

Open the config and paste at least one webhook:

```shellsession
$ sudo nano /etc/gabier/config.toml
```

A minimal config is three lines plus a destination:

```toml
[server]
name = "vps-prod-1"

[discord]
webhook_url = "https://discord.com/api/webhooks/…"
```

Every key is documented in the [configuration reference](/docs/configuration/).

<Callout variant="warning" title="Keeping the secret out of the config file">
  Put it in the environment file instead — the unit already reads it, and nothing then holds a token in a file
  you might copy around:
  <code>sudo tee /etc/gabier/env &lt;&lt;&lt;'GABIER_DISCORD_WEBHOOK=https://discord.com/api/webhooks/…'</code>
  then <code>sudo chmod 600 /etc/gabier/env</code>.
</Callout>

## Verify, then start

`check` validates the config and actually reaches the webhook, without posting anything to your channel.
`test` posts one real message.

```shellsession
$ sudo -u gabier gabier check --config /etc/gabier/config.toml
config    /etc/gabier/config.toml
serveur   vps-prod-1
source    journald (ssh, sshd)
évènements accepted=true failed=true invalid_user=true closed=false
anti-spam 1 échec(s) par IP, puis résumé toutes les 300s
geoip     false
discord   https://discord.com/api/webhooks/123/abcd…
          joignable

Tout est prêt.
$ sudo -u gabier gabier test --config /etc/gabier/config.toml
$ sudo systemctl start gabier
$ sudo journalctl -u gabier -f
```

<Callout variant="warning" title="Now open an SSH session from another machine.">
  Pince should shout in your channel within a second. If nothing shows up, jump to
  <a href="/docs/troubleshooting/">Troubleshooting</a>.
</Callout>
