How it works

Watch, recognize, shout.

Three stages, three source files, one async pipeline. Here is what happens between someone typing ssh and your phone buzzing.

sshd Writes to the journal Accepted publickey for …
source.rs Streams lines journalctl --follow, or a rotation-aware tail
event.rs Parses & filters 3 regexes, ignore lists, event toggles
notify/*.rs Posts webhooks Discord embed, Slack Block Kit, one task each
01 · Watch

Reading the journal without owning it

On a systemd host Gabier spawns journalctl --follow --lines=0 --output=cat filtered on the sshd unit and reads its stdout line by line. Starting at zero lines means a restart never replays old logins. If journalctl exits, Gabier waits three seconds and spawns it again.

With kind = "file" it opens the log, seeks to the end, and polls the size every 500 ms. A file that shrinks or vanishes means logrotate ran; Gabier reopens it from the start of the new file.

// source.rs — journald
let mut cmd = Command::new("journalctl");
cmd.args(["--follow", "--lines=0", "--output=cat"]);
for u in units { cmd.arg("--unit").arg(u); }

while let Some(line) = lines.next_line().await? {
    tx.send(line).await?;   // bounded channel, 256
}
// event.rs
pub enum SshEvent {
    Accepted { user, ip, port, method, key },
    Failed   { user, ip, port, method, invalid_user },
    Disconnected { user, ip, port },
}

02 · Recognize

Three regexes, nothing clever

sshd's log lines have been stable for a very long time. Gabier matches exactly three of them: Accepted, Failed and Disconnected from user. Anything else, including the pam session noise, is dropped before it costs anything.

A matched event then goes through the toggles and the ignore lists from [events]. The parser is pure and covered by unit tests, so a distro that formats a line differently is a one-line fix with a test.

03 · Shout

One task per channel, never blocking

Each channel implements a tiny Notifier trait. For every event, Gabier spawns one task per channel; a Discord outage never delays Slack, and neither delays reading the next line. Requests time out after ten seconds and a failure is logged, not retried, so a flapping webhook cannot pile up a queue.

// notify/mod.rs
pub trait Notifier: Send + Sync {
    fn name(&self) -> &'static str;
    fn send(&self, n: &Notification) -> BoxFuture<Result<()>>;
}

// main.rs
for notifier in &notifiers {
    tokio::spawn(async move { notifier.send(&n).await });
}

The security model

What Gabier can touch, and what it cannot, when started from the shipped unit.

Can
Read the journal (group systemd-journal)
Read /etc/gabier
Open outbound TCP to your webhooks
Cannot
Write anywhere but /tmp (private)
See /home, devices, kernel tunables
Gain privileges or run writable+executable memory
Trust
The webhook URL is the only secret. Keep the config 600. Rotate the webhook if it leaks; nothing else is exposed.
